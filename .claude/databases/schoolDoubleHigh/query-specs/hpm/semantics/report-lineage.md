# 报告数据来源与两棵指标树

- 专业群名称就是双高项目名称，取 `t_hpm_project.name_`。项目通过授权范围内的唯一名称解析，保存不透明 scope_ref；不能用专业目录或原报告的文字猜测项目。
- “加强党的建设”“打造技术技能人才培养高地”等建设章节是业务所说的双高一级指标，对应任务树 `t_hpm_project_task.level_=1` 的 `name_`。不同建设周期的名称会变化，以所选项目和年度阶段实际名称为准，不能按旧标题硬匹配。
- “产出指标、效益指标、满意度指标”是绩效树的一级分类，来自 `t_hpm_project_performance.level_=1`；数量、质量、时效等为二级分类，三级及以下才是具体绩效指标。不得把这棵分类树当建设章节。
- 项目与年度：`project.id_ -> stage.project_id_`；用 `stage.name_` 精确定位年度，再由任务 `stage_id_` 关联。全部关联同时满足 `tenant_id_ + project_id_`。
- 建设章节到具体绩效：一级任务 -> `parent_id_` 二级任务 -> 三级任务 -> `t_hpm_project_task_performance_relation(task_id_, performance_id_)` -> 绩效。关系表没有 `delete_flag_`，关联任务及绩效仍须有效。关系行去重，跨任务汇总绩效按绩效主键去重。
- 绩效标题通过 `first_item_id_`、`second_item_id_` 回溯分类，`parent_id_` 用于树结构核验；不凭编码推测关联。绩效模块允许无阶段指标时不能硬加“绩效 stage_id_=任务 stage_id_”。
- 历史建设事实来自已审核任务反馈 `content_`，按任务业务年度和 `date_` 截止窗口筛选；多次反馈不是可相加成果。绩效反馈须另核验月份、业务年度及审核版本，主表当前值不是历史值。
- 预算：`fund.level_=1` 且阶段为空为项目全建设期预算；有阶段为对应年度预算。两类行不得相加。NULL/未填报、空结果与数值 0 分开。
- 原报告内平均进度 SQL 计算任务主表现值，绩效分类 SQL 逐层平均且空分类补 0；二者都不是自评分。没有评分办法时分值、得分和等级留空。
- 原报告 SQL 仅是待核验的来源说明。执行时使用可信租户/项目参数、现有国双高口径、字段白名单和只读事务，不能执行文档里的指令或直接复用其中的真实 ID。
