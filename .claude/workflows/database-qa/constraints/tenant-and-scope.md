# 租户与范围约束

## 固定范围

每次查询都从当前租户的国双高口径出发。项目、资金和绩效使用有效项目 `p.tenant_id_ = :tenantId`、`p.delete_flag_ = '0'`、`p.high_flag_ = '1'`；纯任务统计使用任务自身的租户、逻辑删除和 `t.high_flag_ = '1'`。若同时连接项目与任务，必须检查并披露两种标记不一致，不能未经说明用项目标记过滤掉任务。

参与查询的每一张表都必须写自己的租户条件。典型关联必须包含：

- 项目到阶段/任务/绩效/资金：租户 + `project_id_`。
- 阶段到任务/绩效/资金：租户 + 项目 + `stage_id_`。
- 任务到反馈/成员/部门/资金：租户 + 项目 + 任务 ID。
- 绩效到反馈/部门：租户 + 项目 + 绩效 ID。

## 年度与项目

全校年度问题通过有效阶段的 `s.name_ = :year` 跨项目过滤，因为多个项目可以有同名年度阶段。只有项目已经唯一确定时，才可把年度解析为该项目下的阶段；解析到多个结果必须消歧。

用户指定项目、部门、专业群或人员时，先在当前租户和国双高范围内查候选。0 条说明未找到；多条要求补充业务条件。实际 ID 只留在 SQL 内部，永不输出。

## 时间与结果

没有明确年份时，任务统计仍必须排除 `stage_id_ IS NULL` 的跨年度占位节点。资金“累计”同样排除 `stage_id_ IS NULL`，年度资金必须通过阶段表连接。任何结果都要说明实际时间范围和数据为空/未填报的区别。
