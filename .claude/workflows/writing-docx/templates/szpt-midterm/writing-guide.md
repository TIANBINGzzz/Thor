# 深职大双高中期自评报告逐段撰写指南

本指南只对应 `szpt-midterm`。逐段规则来自已确认的逐页来源记录；指标含义、参数、输出和已验证 SQL 只维护在 `schoolDoubleHigh/hpm` 主题指标 YAML，本文仅引用指标 ID。`document-map.json` 提供可选位置、表格关系和遗漏提示，`report-data-plan.json` 提供推荐取数项；文中的物理页和位置ID仅供参考，实际编辑依据当前DOCX结构。

## 逐段执行规则

1. 读取本段原文、上下文和下列对应规则，判断属于元信息、事实表格、分析正文、混合内容还是结构内容。
2. 先用 `project_catalog`、`stage_catalog` 确定对象和年度；专业群名称取国双高项目名称。学校范围必须独立授权，不能用两个专业群合成学校数据。
3. 按本段列出的指标取证。指标无结果只代表该范围未取得记录；反馈正文为简短数字或测试文字时，不足以支持成果结论。
4. 有证据写有对象、期间和单位的结论；证据不足写有限结论及缺口；完全无证据沿原段主题写分析框架、具体数据需求和后续动作。后两种状态标黄。
5. 不照抄模板样例，不用当前值替代历史快照，不从目标/完成值自行计算评分、等级或终期完成度。未定义项不执行临时 SQL。
6. 按原模板主题完成授权范围内的正文和表格，可按内容需要拆分段落，不以旧地图位置数量作为完成标准。保留表格行列和单位；未知项写具体缺口，不留空、不填斜杠、不填默认 0。未编辑内容中的例数和成果仍须核查。

## 已整理段落

以下规则提炼自逐页核对记录。来源SQL已确认不等于样例实绩、评分规则或表格展示方式已确认；表2展示方式等未决项继续保留，不能因迁入本指南自动视为用户确认。

### G01 封面、题名和目录（物理页1-3）

- 主题：学校品牌、报告类型、署期和最终目录。
- 来源：品牌素材及本次报告要求，不使用业务 SQL。报告署期与统计截止日分开。
- 必查：封面图片内校名不能只靠正文替换；目录按最终标题层级和实际页码重建，不保留“键入章标题”等样例。

### G02 总体目标概述（物理页4，`P0034`）

- 来源指标：`project_catalog`、`stage_catalog`、`task_level_counts`、`task_progress_summary`。
- 撰写：分别说明学校和两个专业群的对象、期间、三级任务数量及平均进度；只有学校范围获准后才能写学校值。
- 必查：均值不能证明每项超过100%；年度进度不是中期或终期累计完成度。累计完成度、自评得分和等级缺少规则，按缺口处理。

### G03 自评得分表（物理页5，`T01`）

- 来源指标：`project_performance_categories` 仅提供一二级分类目录。
- 撰写：保留学校建设任务、专业群建设任务及原表合并单元格结构。
- 必查：分类目录不证明适用评分表版本；权重、得分和等级须由评价办法及评分证据提供，不能用任务进度推导。

### G04 标志性成果综述及表2（物理页9-12，`T02`）

- 来源指标：`task_tree`、`task_feedback_candidates`；附件和认定文件作为成果证据。
- 撰写：按名称、时间、级别、数量、单位和证据归类成果，综述只能概括已核实事实。
- 必查：反馈条数不是成果数；空反馈或测试文字不证明没有成果；新增与累计、人数与人次、人日、名次与数量分别处理。“唯一”“领先”“均列第一”和领导评价须有独立材料。
- 未决：表2是否按实际成果增减原93个栏目尚未确认；当前沿用原结构，逐格写已核实事实或具体缺口。

### G05 经费到位和执行概述（物理页13，`P0511`）

- 来源指标：`project_cycle_budget`、`fund_totals`、`fund_source_amounts`。
- 撰写：全建设期预算使用无阶段一级资金节点；年度到位和执行使用指定年度一级资金节点。原单位为万元，展示亿元时除以10000。
- 必查：到位/预算、执行/预算、执行/到位三个比率分母不同；全周期和年度不能交叉替代。学校自筹对应 alone 字段，其他来源不擅自归并。

### G06 党建与立德树人（物理页14，`P0515-P0517`）

- 来源指标：`task_tree`、`first_task_progress_feedback`、`task_feedback_candidates`。
- 撰写：按本周期任务树定位一级任务及下属三级任务；已确认本周期编码1对应“落实立德树人根本任务”，据反馈和附件归纳党建、课程思政及实践育人成果。
- 必查：该编码关系只适用于已确认周期，不能推广到所有章节；成果按事实去重，不能数反馈行。

### G07 技能人才培养高地（物理页14-20，`P0519`、`T03`、`P0634-P0635`）

- 来源指标：`task_tree`、`task_performance_links`、`task_feedback_candidates`。
- 撰写：表3-1按本节三级任务筛选关联绩效，按绩效 ID 去重，保留定性值和原单位；正文再结合反馈及佐证写培养质量与教学成果。
- 必查：新增与累计、建设计划与实际投入分开；就业率、重点企业就业和比较性薪酬须有届别、分母、对照范围及期间。目标/完成值不自动产生完成率和得分。

### G08 技术技能创新服务平台（物理页21-22，`P0637`、`T04`、`P0753-P0754`）

- 来源指标：`task_tree`、`task_performance_links`、`task_feedback_candidates`。
- 撰写：表3-2按本节任务范围取关联绩效；正文从反馈及佐证提取科研项目、平台、到账经费、标准、专利、企业服务和成果转化。
- 必查：科研到账、横向到账、成果转化款与双高建设资金是不同口径；论文括号值为子集时不重复相加；名次不是数量。

### G09 高水平专业群（物理页22-25，`P0757`、`T05`、`P1000`、`P1022`）

- 来源指标：`task_tree`、`task_performance_links`、`task_feedback_candidates`、`project_catalog`。
- 撰写：表3-3按绩效 ID 去重；正文结合规划和专业产业对应材料写专业布局、课程教材资源、交流合作及示范推广。
- 必查：专业群名称来自项目名称，但项目名称不能证明专业、产业和企业关系；28行与正文“27项”的差异保留并披露，不能删行凑数；百分比分母和学生群体分别核对。

### G10 双师队伍（物理页25-27，`P1024`、`T06`、`P1171-P1172`）

- 来源指标：`task_tree`、`task_performance_links`、`task_feedback_candidates`、`task_members`。
- 撰写：分别处理人员、团队、工作室、岗位、企业实践和兼职教师指标，正文按新增/现有及认定级别组织。
- 必查：人次不转换为不重复人数；企业实践“人/日”须核对是否人日；多项荣誉不能直接相加得人才总数。
- 来源边界：`task_members`仅用于核对建设任务负责人和参与人，不能当作全校教师数、双师型教师数或企业实践人数。

### G11 校企合作（物理页27-28，`P1174`、`T07`、`P1224-P1225`）

- 来源指标：`task_tree`、`task_performance_links`、`task_feedback_candidates`。
- 撰写：保留产业学院、职教集团、学徒制专业和定性机制等不同粒度；从反馈及材料写合作企业、订单培养、师资交流和培训。
- 必查：成果项数不等于目标项数；企业、学院、专业、教师分别去重，交叉教师群体不能相加。

### G12 服务发展（物理页28-29，`P1227`、`T08`、`P1325-P1326`）

- 来源指标：`task_tree`、`task_performance_links`、`task_feedback_candidates`。
- 撰写：区分学历继续教育、非学历培训、师资培训、基地和对口帮扶，保留人数、人次和人日单位。
- 必查：年均值、累计值和报告期值不能混用；正文项目数与表格完成值不一致时核对范围和截止日。

### G13 学校治理（物理页29，`P1328`、`T09`、`P1362-P1363`）

- 必查：排名第一、制度数量和线上事项数量均须对应材料；没有比较范围不写领先。

### G14 信息化（物理页30-31，`P1365`、`T10`、`P1504-P1505`）

- 必查：系统数、事项数、资源量和用户覆盖不能互相替代；“建成”需要运行或验收证据。

## 尚未逐页确认的部分

物理页35“贡献度情况”以下、两个专业群完整章节、措施、经验、问题改进和附件目录尚未完成逐页来源确认。处理这些位置时沿用原段主题和结构，先检索已有指标及授权材料；不能把以上学校段落规则直接复制为专业群结论。证据不足时按共同规则完成有限结论或分析框架，并明确待补数据。不得把“尚未确认”解释为删除段落或保留模板样例。

## 全文必查

- 对象：学校、两个专业群分别定位；跨章节同一绩效或成果在汇总时去重。
- 期间：报告年度、截止日、建设周期、预算期间及历史快照分别核对。
- 单位：万元/亿元、人数/人次/人日、项目/平台/专业/团队保持原义。
- 评价：单项完成率、权重、得分、等级和终期累计完成度无规则时保持缺口，不能生成占位 SQL。
- 来源：查询结构正确与业务实绩存在是两件事；NULL、0、无记录、查询失败和未授权必须区分。
