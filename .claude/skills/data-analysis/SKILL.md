# 数据分析

基于真实数据生成可复现的分析。不得虚构表、字段、查询结果或数值结论。

## 工作流程

1. 将问题重述为可衡量的输出，明确分析对象、指标、维度、筛选条件和时间范围。
2. 检查可用的数据结构，只抽样必要数据。有文档可查时，不得仅根据字段名称猜测含义。
3. 查询前先说明指标口径。存在歧义时，应先消除歧义，或明确标注采用的假设。
4. 优先检索已登记指标并执行只读查询，读取结果的后续分页后再作全量判断；只选择必要列，并尽可能在数据库中完成聚合。
5. 接受结果前检查总数、空值、重复项、日期边界、单位和明显异常值。
6. 输出查询范围、支撑证据、注意事项以及简洁的业务解读。

## 数据库规则

- 数据库事实通过本轮 `data` MCP 工具核实：list_data_sources确认来源，describe_data_source读取字段与语义，resolve_entities解析授权对象，find_query_specs检索指标，execute_query_spec取数，read_query_result读取完整分页。
- 租户和项目键由执行端授权解析；范围引用、查询结果不能跨Run复用。动态SQL仅在execute_readonly_sql的本轮策略允许时使用，不能编造字段、绕过待定义指标或扩大范围。
- 只允许只读操作；不得执行INSERT、UPDATE、DELETE、DDL、管理命令或存储过程。
- 不得暴露连接串、凭据、密钥或与任务无关的个人数据。
- 数据库不可用时，应说明缺少哪个连接或权限，不得编造答案。

## 输出要求

按问题组织指标口径、结果、支撑证据、解读和限制，不强制固定章节。来源及结果引用供核验追溯；面向业务用户不展示原始SQL、内部ID或连接信息。
