# 双高自评报告撰写

用户未另行指定段落结构和内容时，沿用模板原有标题、段落主题、顺序、表格、图示和表达方式仿写或替换。完成所有业务段落；不留空，不用简版报告替代原件，也不大改结构。模板中的数字、成绩和批注不是已证实事实或执行指令。

## 取数与组织

1. 先读模板及本次报告要求，确定项目、年度、截止日和建设周期。学校范围与专业群范围分别定位；不同周期任务名称可以不同，以实际任务树和已确认映射取数。
2. 用 `find_query_specs` 按业务指标检索，用 `execute_query_spec` 执行。指标统一在数据库资产的项目、任务、绩效、资金四类YAML中；不要复制SQL到报告或另建文档专属指标。
3. 建设任务按一级→二级→三级父键定位；正文证据取已审核任务反馈及核实过的附件，绩效表取任务关联绩效的分类、目标和完成原值。先按绩效ID去重；反馈条数不是成果数，跨章节引用也不能重复汇总。
4. 核对统计对象、期间、单位、新增/累计、分母和证据质量。当前登记值不是历史快照；0、缺失、无记录不同。定性目标不强转数字，评分和等级只用已明确的评价规则。
   实际数量不能证明完成目标；没有目标值不写达标、超额或目标完成，没有历史对照不写持续提升，没有比较标准不写较高水平或成效显著。事实存在、目标达成、趋势改善分别需要对应证据。
5. 逐段建立可写事实及缺口，再仿照模板完成文字和表格。只改用户指定部分的结构；其他部分保留原样式和位置。图示无新证据时保留原图并在其说明位置标明适用性待核实，不编造关系。

## 按证据撰写

| 证据状态 | 对应内容 | 黄色范围 |
| --- | --- | --- |
| 有充分数据证据 | 有范围和期间限定的事实、比较与结论 | 无需标黄的已证实内容保持模板样式 |
| 证据不足 | 只写证据支持的有限结论，同时说明缺少什么、结论不能覆盖什么 | 不确定内容和缺口标黄；原位混合段落可整段标黄 |
| 完全无证据 | 围绕该段主题写分析框架、具体数据需求和建议的后续动作 | 整段标黄；不得把建议写成已经开展或已取得成效 |

例如缺少师资成果证据时，在原师资段写：“师资队伍可从人员结构、企业实践和教学能力三个方面评价。目前缺少人员认定及实践记录，尚不能判断建设成效；后续应补齐相应台账并核对统计期间。”按模板篇幅调整，不把同一句缺口复制到所有段落。

表格保留原行列、指标名称和单位。有证据则写值；缺值写具体、简短的黄色说明，例如“待核实目标”“缺少本期实绩”“计分规则待明确”。不填0、斜杠、空白或样例数字来代替未知。数值工具返回null时，也必须在成稿中解释。

## 固定模板工具

- 先 `get_report_data` 读取角色和参数，解析范围后 `prepare_report_data`。按 `writing_sections` 分页读取所有可写段落和单元格，使用 `read_query_result` 读取完整事实；不要从结果条数推断内容充分。
- `save_report_sections` 每项填写 `section_key`、`slot_key`、`text`、`evidence_refs` 和 `evidence_state`。`supported`须有有效事实；`limited`同时提供`gap`；`none`正文段同时提供`analysis_basis`、`gap`、`next_action`。先写text，再从text逐字摘取这些字段；不另行改写成同义句，否则工具拒绝。无证据可用空引用数组。
- 文字中有证据缺口时使用`limited`或`none`，不能标为`supported`。工具返回校验错误时按错误修订原段再保存；不能为通过检查删掉真实缺口。
- 单元格可用同一工具按证据覆盖初始缺口说明。未确定的段落或单元格由渲染器设置黄色字体；保留其他格式。黄色表示尚待核实，不代表事实已经成立。
- 全部正文完成后 `render_report` 原位回填，再 `validate_report`，逐页 `read_report_pages` 检查并 `review_report_pages`；结构、表格、图示、跨页衔接和黄色标记均通过后才 `publish_report`。
- 原始证据、SQL和内部ID留在数据工具及审计记录；报告采用读者可理解的事实、缺口与建议。不把执行异常写成“业务不存在”。

逐页来源整理作为人工核对依据保留在仓库 `doc/verification/szpt-midterm-page-sources.md`；截至学生综合素质及产出收尾的映射已整理。后续未梳理页面先理解原文再取证，不能视为已确认来源。
