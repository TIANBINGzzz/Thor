## 一个资产记录什么

`hpm/specs/<id>.json` 保存业务含义，`hpm/sql/<id>.sql` 保存参数化 SQL；JSON 使用现有工具即可读取，SQL 可独立审查。

| 字段 | 含义 |
| --- | --- |
| id / version / name / description | 稳定内部标识、版本、名称和业务定义 |
| source_keys / tables | 可适配的逻辑源及实际业务表；同名字段不代表两个源已验证等价 |
| grain / semantics | 一行或一次聚合代表什么、统计口径、时间、去重和空值规则 |
| parameters | 类型、必填性、来源及默认绑定；null 也是明确选择，不能默认为扩大查询范围 |
| sql_file / output | 查询文件、每个输出字段的名称、含义、类型、单位、空值及内部可见性 |
| prerequisites / requires_queries | 执行前条件和依赖查询；诊断失败必须停止，不能忽略条件直接调用 SQL |
| validation / result_policy | 结果约束、完整性检查与输出边界；文字规则目前不等于已实现自动校验 |
| evidence / verification | 定义依据和逐数据源验证记录；字段可用不等于历史实绩或生产链路已验收 |
| status / blockers | defined：定义完成；blocked：有 SQL 但仍不可启用；needs_definition：暂不编造 SQL |

路径基准：`sql_file` 相对该业务目录（`hpm/`）；`evidence`、`source_document` 及数据源配置引用相对仓库根；不记录宿主机绝对路径。

## 取数约定

1. 先按业务含义、粒度、期间及获准数据源检索 QuerySpec，命中后绑定参数并执行，不能只按关键词套用。
2. `tenant_id` 和授权项目范围由可信执行端确定；QuerySpec 不从数据库内容推导业务授权。名称候选多条时消歧，不能 `LIMIT 1` 静默选择。
3. SQL 中 `:name` 是逻辑命名参数，必须由执行适配器使用数据库驱动参数绑定；不做字符串拼接。当前 DBHub `execute_sql` 不支持命名参数，不能直接发送这些 SQL，执行适配仍待实现。
4. 无匹配资产但语义、字段和范围已知时，可以动态生成只读 SQL；缺业务定义、历史快照或授权时，动态 SQL 也不能补足，需留空高亮或问询。
5. 动态查询经口径确认和验证后再作为新版本资产入库，不能由模型自动改写已批准的查询定义。
6. `source_key` 选择可信服务端绑定，不拼接数据库名；`report_db` 未连接时不回退到 `qa_db`，数据或名称不同不否定既定来源。
7. 年度按阶段名称；当前主表值不证明历史截止日状态。反馈提交时间不是业务年度，累计反馈版本不跨年相加。
8. 来源、查询版本、非秘密口径与结果引用在 Run 内关联；业务原始值、内部 ID、凭据不得写入仓库。对外文档不展示内部 ID 或附件原始地址。
