# ADR-004: 引用语法处理大候选集

日期: 2026-08-17
决策状态: 已采纳
实现状态: 已实现
替代: 无
被替代: 无

## 背景

需要让用户从大列表（几千到几万条）中选择一项，但把候选集喂给模型不可行：消耗大量 token 且与任务无关。

## 决策

使用 `@type:value` 引用语法，模型只拿引用标记，候选集留在服务端：
- 前端打 `@` 触发面板，按 `/api/options` 分页拉取（20 条/页，上限 50）
- 服务端在 `referencePromptContext()` 复核每条引用，命中才给真实描述
- 不存在的引用明确标记"不存在，不要凭猜测使用"

## 后果

### 好处
- 成本与候选集大小无关（243 个包从 7 KB 降至 463 字节）
- 扩展到十万级时只需把 `list()` 换成数据库查询，接口形状不变
- 前端传来的标签不被采信，服务端强制复核

### 代价
- 需要自建引用解析和选择器 UI
- 中文标点和作用域包名的 `@` 符号需要特殊处理

### 风险
- 服务端复核逻辑必须覆盖所有数据源类型
