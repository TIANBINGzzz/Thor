Python Runtime 接口

本文档是 Python Runtime 提供给 Java 业务层的接口契约。Java 负责业务会话、用户权限和文件 ACL；Python 负责 Capability 执行、SDK 会话、Run 状态、事件和交付物。

目录

变更规则

  1. 字段、路径、状态、事件、JWT Claim 或 File Broker 头发生变化时，同步更新 Runtime 规范、Java 设计、本文档和协议测试。
  2. 请求与响应示例必须能按当前 Python Runtime 代码解析；页面只保留当前代码已经接入的接口。
  3. Capability 目录只读；执行通过 Run 的 capabilityRef 选择，内部执行配置由 Python 维护。
  4. 本地自测通过中间层模拟 Java，不改变本页面记录的 Java 接口契约。

基础约定

Base URL由部署配置提供；本文路径均相对于 <RUNTIME_BASE_URL>。
调用方向Java 业务层调用 Python Runtime；浏览器不直接调用这些接口。
Content-TypeJSON 请求使用 application/json；事件使用 text/event-stream；交付物下载返回文件二进制。
鉴权请求头以下所有 Run 接口都必须发送 Authorization: Bearer <Run JWT>，包括 SSE 和 Artifact 下载。credentials.platformBearer 仅用于业务 MCP，不能代替 Run JWT。
字符集UTF-8。
ID字母、数字、_、-，首字符必须为字母或数字，长度不超过 256。
Run 状态queued、running、waiting、succeeded、failed、cancelled。
Java 只提交业务字段和 capabilityRef。Workflow、Skill、MCP、模型、工作目录、工具参数和 Provider Session 均由 Python Runtime 内部决定。

创建 Run

POST/internal/v1/runs

Java 为每次执行生成唯一 runId 和 messageId，签发带 run.execute scope 的 Run JWT，然后提交请求。相同请求重试保持原 runId，并用新 jti 签发 Run JWT。SDK 的 session_id 由 Python 内部关联，不替代此执行标识。

Request headers
Authorization: Bearer <Run JWT>
Content-Type: application/json
Request body · agent-run/v1
{
  "protocol": "agent-run/v1",
  "runId": "run_01",
  "messageId": "message_01",
  "businessSessionId": "session_01",
  "capabilityRef": "document-writing",
  "payload": {},
  "input": {
    "text": "请整理这个文档",
    "attachmentRefs": [
      {"fileId": "file_01", "purpose": "input"}
    ]
  },
  "credentials": {
    "platformBearer": "业务 Token"
  }
}
字段类型必填设计原因和约束
protocolstring是固定为 agent-run/v1，用于识别请求协议。
runIdstring是一次执行的幂等键；同一 ID 的不同请求会被拒绝。
messageIdstring是关联 Java 业务消息；不等同于 Provider Session ID。
businessSessionIdstring否关联连续业务会话；Python 用它选择内部 Session，但不把它当作 Provider ID。
capabilityRefstring / null否普通会话省略或null，内部使用conversation，JWT仍须绑定conversation；选择能力只作用于当前消息，空字符串拒绝。
input.textstring条件必填最长 1,000,000 字符；文字、附件、payload 至少一个非空；input 对象仍必填，可以为 {}。
payloadobject否省略等同于 {}；当前仅 document-writing 选择预制模板时传 templateKey，不得自行添加字段。参与幂等比较，详见业务 payload 规范。
input.attachmentRefsobject[]条件必填最多 64 项；每项使用 fileId 和 purpose，用途只能是 input 或 reference。
credentials.platformBearerstring否仅供受信 MCP 使用；不写入 Prompt、事件、日志或 Run 存储。

新 Run 返回 202；相同请求的幂等重提交返回 200。

Response 202 / 200
{
  "run": {
    "runId": "run_01",
    "status": "queued",
    "lastSequence": 0
  },
  "eventsUrl": "/internal/v1/runs/run_01/events"
}
创建、查询、控制和取消共用精简 Run 响应：runId、status、lastSequence，失败时可带 error。身份、业务关联和 SDK 执行信息仅在 Python 内部保存。

业务 payload 规范

payload 用于传递当前能力已明确约定的参数，不是任意业务数据的扩展容器。当前唯一约定字段是 document-writing 的 templateKey，用于选择 Python 已登记的预制模板；其他场景省略 payload 或传 {}。

接入方不得自行新增键名或猜测字段用途。标题、年份、统计范围、写作要求等写入 input.text，文件使用 input.attachmentRefs。后续增加字段须先明确能力、类型、允许值、处理逻辑并更新接口约定。SSE 事件中同名的 payload 是另一套事件数据结构，见SSE 事件。

通用格式与限制

项目现行约束
顶层类型必须是 JSON 对象。允许省略或传 {}；直接传 null、数组、字符串、数字或布尔值会返回 400。
字段与值当前仅允许按下表使用 templateKey，值为已登记且启用的模板标识字符串。不要传自定义键名、嵌套对象、数组或其他类型作为能力参数。
大小Python 重新序列化后的 UTF-8 JSON 不超过 65,536 字节（64 KiB），包含键名、标点等开销；不是字符数，也不是只计算字段值。中文通常占多个字节，建议留出余量。
层级根 payload 记为第 0 层，每进入一个对象字段值或数组元素增加 1 层；检查到的任意值深度不得超过 16。
非空请求input 对象始终必填；去除首尾空白后的 input.text、非空 attachmentRefs、非空 payload 至少满足一项。仅传 payload 时也要提供 "input": {}。
生效范围属于当前 Run；不会作为后续消息的默认请求配置。下一次选择能力或预制模板时应重新显式传值。

现行大小计数使用 Python json.dumps(payload, ensure_ascii=False, allow_nan=False) 后的 UTF-8 字节数，含其默认分隔符空格；压缩 HTTP JSON 中的空白不能绕过此限制。

national-excellence-data-qa省略或 {}没有专属必填字段。问题、年份和范围要求放 input.text；查询和来源权限由服务端控制。
document-writing：普通撰写省略或 {}不选择预制模板时不传字段。修改文档或上传模板使用附件引用。

示例二：选择已登记的预制模板

字段类型 / 条件含义
payload.templateKeystring；使用预制模板时填写当前登记值为 szpt-midterm，仅用于 document-writing。大小写敏感，不能自行编造模板标识；新增值须由 Python 完成模板登记、启用及能力绑定。
完整请求：document-writing + 系统预制模板
{
  "protocol": "agent-run/v1",
  "runId": "run_template_01",
  "messageId": "message_template_01",
  "businessSessionId": "session_01",
  "capabilityRef": "document-writing",
  "input": {"text": "生成截至2025年底的双高中期自评报告"},
  "payload": {"templateKey": "szpt-midterm"}
}

templateKey 只能选择 Python 已登记、启用且绑定当前能力的模板；它不是文件路径、数据库名、模板版本或权限参数。模板年份、截止日期和写作要求放在 input.text，外部材料仍使用 input.attachmentRefs。当前 szpt-midterm 由 Runtime 绑定 schoolDoubleHigh 数据源和 hpm 领域查询，Java 不提交连接、SQL、路径或密码。未知、停用、未授权或完整性校验失败的模板会在执行前失败。national-excellence-data-qa 不需要专属 payload 字段，问题、年份和范围要求放在 input.text。

不选择预制模板时省略 templateKey，不传 null、空字符串或自定义值。当前代码将 null 当作未选择，但这不是推荐的接入写法。字段名必须精确为 templateKey；其他拼写不在约定内。其他能力不得传此字段。错误类型、非法标识、未登记、停用或能力不匹配的模板会在执行准备阶段失败。

示例三：上传自定义模板

模板位置Java 传值Python 处理
Python 已登记的系统预置模板payload.templateKey；要求放 input.text校验并加载预制模板，使用绑定的报告流程；模板文件不经 File Broker。
Java 保存的用户自定义模板input.attachmentRefs；不传 templateKey；正文明确模板文件和要求经 File Broker 获取文件，走普通撰写：读取结构、按需收集事实、组织正文、生成新 DOCX；不自动注册预制模板。
自定义模板完整请求
{
  "protocol": "agent-run/v1",
  "runId": "run_custom_01",
  "messageId": "message_custom_01",
  "capabilityRef": "document-writing",
  "input": {
    "text": "以附件《自评报告模板.docx》为模板，保留章节和表格，结合可用数据撰写2025年度报告；证据不足时写有限结论和具体缺口，无证据时按原主题写分析框架、数据需求及后续动作，不确定内容用黄色字体，不留空。",
    "attachmentRefs": [{"fileId": "file_template_01", "purpose": "input"}]
  }
}

当前 purpose 仅支持 input / reference，不支持 template；多个附件通过正文明确模板与参考资料。Java 保存文件，Python 按本次授权获取工作副本；再次使用须重新提交附件引用，无需为每个上传模板建立 Python 配置。数据库工具仅在已配置且获准时可用，文件上传不授予数据权限。

若同时传 templateKey 和附件，仍走该预制模板分支，附件不会替换模板。以上附件传递与普通撰写入口已有实现，复杂自定义模板的版式保真和取数质量仍需真实文件验收。

保留字段与数据边界

任意层级（包括数组内对象）均拒绝以下键名，比较时忽略大小写、下划线和连字符。例如 apiKey、API_KEY、api-key 都会被拒绝：

禁止作为 payload 对象键名的字段
credentials, platformBearer, authorization, token, apiKey, secret,
tenantId, userId, workflowRef, skill, skills, agent, agents,
model, tools, mcp, mcpServers, mcps, cwd, workspace, permissions

这是字段名检查，不是秘密识别或内容脱敏。将密码换个键名、放进字符串或 Base64 并不会变安全。payload 会被模型读取并可能出现在回答或运行记录中；不得放密码、Token、个人敏感身份信息、连接凭据、文件字节或执行配置。业务凭据走 credentials.platformBearer，模型和数据库配置由部署侧维护。

返回、重试与失败处理

payload 没有独立返回接口。创建成功仍返回 Run 状态及 eventsUrl，查询 Run 和会话执行列表不会原样回传请求 payload；模型生成结果通过 SSE 或 Artifact 获取，不承诺与输入字段一一对应。

阶段 / 结果含义与处理
400：请求格式错误payload 顶层类型错误、保留字段、非 JSON 值、超出大小或深度限制等，会在创建时拒绝。通常返回 text/plain 错误信息；修改输入后再提交。
409：幂等冲突同一 runId 已登记后，修改合法 payload 或其他参与幂等比较的业务字段会冲突。改变业务输入应使用新 runId。
202 / 200：请求已接收首次创建通常返回 202，相同请求重试返回 200。重试保留原业务字段，并以新 jti 签发 JWT；payload 省略与 {} 等价，null 不等价且非法。
后续 run.failed模板资源与能力绑定等检查发生在异步执行准备中；可能先返回 202，再通过 SSE 报告 run.failed，查询状态为 failed。不能将 202 当作模板已通过或文档已生成。

请求格式检查、模型处理和模板资源校验是不同阶段；例如 {"templateKey": "unknown-template"} 可以通过通用 JSON 检查，但随后会因模板未登记而失败。Java 应同时处理创建接口的 HTTP 错误和执行过程中的失败事件。

查询 Run

GET/internal/v1/runs/{runId}

使用 run.read 或 run.execute scope。查询请求不消耗 JWT 的 jti。

Response 200
{
  "run": {
    "runId": "run_01",
    "status": "running",
    "lastSequence": 3
  }
}
字段说明
runIdJava 提交的执行标识，用于关联业务消息、查询和控制。
status当前 Run 状态；创建成功仅代表已接收，不代表模型执行完成。
lastSequenceRun 当前已持久化的最大事件序号；0 表示尚无事件。它用于了解事件进度，不是 SDK resume 标识。续传应使用 Java 已成功处理的事件序号，不能直接用查询所得值跳过未消费事件。
error可选；Run 失败时保存的稳定错误码。

按业务会话查询执行记录

用于查询某个业务会话在 Python Runtime 中发起过哪些执行，以及每次执行的当前状态。例如用户重新打开会话时，Java 可通过此接口取得 Run 列表，再按 messageId 关联自己保存的业务消息，显示“执行中”“已完成”或“失败”等状态。

查询范围是 JWT 授权的同一租户、同一用户、同一业务会话，包含该会话下各能力的执行摘要。接口不返回聊天正文、会话标题、内部 metadata 或 SDK 会话；业务会话和消息仍由 Java 保存。需要执行详情、事件或生成文件时，取得 runId 后调用对应的 Run 接口。

GET/internal/v1/sessions/{businessSessionId}/runs

输入：会话标识与分页参数

此接口没有请求体。会话标识放在路径中，分页参数放在 URL 中，JWT 放在请求头中。

参数位置 / 类型说明
businessSessionId路径 / string必填。Java 维护的业务会话标识，例如 session_01；必须与 JWT 中的同名字段一致。
limit查询 / integer可选，每页最多返回的记录数。默认 50，范围 1–100。
cursor查询 / string可选，最长 345 字符。第一页不传；下一页使用上一页返回的 nextCursor，不要自行生成或修改。
请求示例：查询 session_01 的第一页
GET /internal/v1/sessions/session_01/runs?limit=50
Authorization: Bearer <包含 session.read 权限的 JWT>
Accept: application/json

鉴权：Java 签发会话读取 JWT

Java 先校验当前用户是否有权访问该业务会话，再使用与 Python 约定的密钥签发短期 HS256 JWT。以下是签名前的 claims 示例，不是请求体，也不是可以直接放进 Authorization 的 Token：

会话读取 JWT 的 claims 示例
{
  "iss": "string-ai-center-service",
  "aud": "ccsdk-runtime",
  "iat": 1725400000,
  "exp": 1725400600,
  "jti": "session_read_01",
  "tenant": "tenant_01",
  "sub": "user_01",
  "businessSessionId": "session_01",
  "scope": "session.read"
}

以上字段均必填。iss、aud 必须匹配部署配置；tenant、sub 来自 Java 已认证的租户和用户。示例时间仅说明格式，实际签发时将 iat 设为当前 Unix 秒、exp 设为短期过期时间。这里不要求 runId 或 capabilityRef。

只读分页不消耗 jti，同一 Token 可在有效期内查询多页。run.read / run.execute 不能代替 session.read；反过来，会话读取 Token 也不能直接查询或控制单个 Run，调用那些接口需要另行签发对应 Run JWT。

分页与错误处理

记录按创建时间倒序排列，创建时间相同时按 Run ID 倒序。若 nextCursor 非空，Java 将其作为下一次请求的 cursor 查询参数（由 HTTP 客户端编码），并继续携带有效 JWT。游标本身不授予访问权限。

分页结果不是某一时刻的固定快照；查询期间产生的新记录应通过重新请求第一页获取。成功响应带 Cache-Control: no-store，不得缓存。

HTTP 状态含义
400游标无效，或不属于当前 JWT 授权的租户、用户及会话范围。
401JWT 缺失、无效、过期，缺少 session.read 权限，或 businessSessionId 与路径不一致。
422分页参数不合法，例如 limit 不是整数或超出 1–100，cursor 长度超过 345。

鉴权

Java 签发短期 HS256 JWT，并放入 Authorization: Bearer <JWT>。能力目录无需鉴权，Run 接口使用本节 Run JWT。Python 使用 python/runtime/auth.py 对 JWT 做 HMAC-SHA256 校验。

密钥和部署配置

Python 本地配置位置为项目根目录 .env（参考 .env.example，不是 python/.env）；部署时也可注入进程环境变量。启动时根目录 .env 中的同名值会覆盖进程环境，修改后须重启 Python 服务。唯一密钥配置名为 CCSDK_RUNTIME_JWT_SECRET，不再读取旧别名 SCRIBE_RUNTIME_JWT_SECRET。

Java 对应 Spring 配置项为 ai-center.runtime-jwt-secret（环境变量 AI_CENTER_RUNTIME_JWT_SECRET），必须与 Python 使用相同的密钥值；可通过服务端配置或 Secret/Nacos 注入。下方仅为占位示例，真实密钥不写入本公开文档。建议生成至少 32 字节的随机值，双方使用相同字符串。

CCSDK_RUNTIME_JWT_SECRET非空随机密钥，只放 Java/Python 服务端环境或 Secret Manager，不进入浏览器、代码库、日志和请求正文。

File Broker 回调契约

文件流转

Java 保存的自定义模板与附件流程
用户上传模板或资料 → Java 文件服务器保存并分配 fileId
选择模板 → 前端显示“已选择”
发送消息 → Java 创建 Run（JSON 中传 attachmentRefs）→ Python 立即返回 202
Python 后台：获取授权 → 分块下载 → 校验并落盘 → 文件全部就绪 → SDK 查询
Python → SSE 准备进度和回复 → Java → 前端
生成文件 → Java 调用 Artifact 下载 → 业务归档或用户下载

“上传中”仅用于用户本机向文件服务器上传。Python 获取已存在的模板时显示“正在准备模板”，不是再次上传。Java 不等待下载完成再响应前端；文件字节经 HTTPS 二进制响应传输，进度经 SSE 传输，不把文件放入 payload。当前无附件的 Run 直接执行，有附件但能力不支持时创建返回 400。

用户上传先由 Java 保存并分配 fileId，Java 在创建 Run 时通过 input.attachmentRefs 传递本次授权文件。Python 在执行前获取文件，模型读取准备好的本地文件；payload 中出现 fileId 不会触发下载。Java 可以直接返回代理文件流，无需另设下载 URL。生成文件由 Java 通过 Artifact 接口取得并向用户提供下载。

这是 Java 必须提供给 Python 的文件授权端点。Python 只提交 runId、fileId 和用途；Java 负责业务会话、用户权限、文件 ACL 和授权有效期。
