Python Runtime 接口

本文档是 Python Runtime 提供给 Java 业务层的接口契约。Java 负责业务会话、用户权限和文件 ACL；Python 负责 Capability 执行、SDK 会话、Run 状态、事件和交付物。

目录

变更规则

  1. 字段、路径、状态、事件、JWT Claim 或文件服务请求头发生变化时，同步更新 Runtime 规范、Java 设计、本文档和协议测试。
  2. 请求与响应示例必须能按当前 Python Runtime 代码解析；页面只保留当前代码已经接入的接口。
  3. Capability 目录只读；执行通过 Run 的 capabilityRef 选择，内部执行配置由 Python 维护。
  4. 本地自测通过中间层模拟 Java，不改变本页面记录的 Java 接口契约。

基础约定

Base URL由部署配置提供；本文路径均相对于 <RUNTIME_BASE_URL>。
调用方向Java 业务层调用 Python Runtime；浏览器不直接调用这些接口。
Content-TypeJSON 请求使用 application/json；事件使用 text/event-stream；交付物下载返回文件二进制。
鉴权请求头以下所有 Run 接口都必须发送 Authorization: Bearer <Run JWT>，包括 SSE 和 Artifact 下载。credentials.platformBearer 仅用于业务 MCP，不能代替 Run JWT。
字符集UTF-8。
ID字母、数字、_、-，首字符必须为字母或数字，长度不超过 256。
Run 状态queued、running、waiting、succeeded、failed、cancelled。
Java 只提交业务字段和 capabilityRef。Workflow、Skill、MCP、模型、工作目录、工具参数和 Provider Session 均由 Python Runtime 内部决定。

创建 Run

POST/internal/v1/runs

Java 为每次执行生成唯一 runId 和 messageId，签发带 run.execute scope 的 Run JWT，然后提交请求。相同请求重试保持原 runId，并用新 jti 签发 Run JWT。SDK 的 session_id 由 Python 内部关联，不替代此执行标识。

业务 payload 规范

payload 用于传递当前能力已明确约定的参数，不是任意业务数据的扩展容器。当前唯一约定字段是 document-writing 的 templateKey，用于选择 Python 已登记的预制模板；其他场景省略 payload 或传 {}。

接入方不得自行新增键名或猜测字段用途。标题、年份、统计范围、写作要求等写入 input.text，文件使用 input.attachmentRefs。后续增加字段须先明确能力、类型、允许值、处理逻辑并更新接口约定。SSE 事件中同名的 payload 是另一套事件数据结构，见SSE 事件。

通用格式与限制

项目现行约束
顶层类型必须是 JSON 对象。允许省略或传 {}；直接传 null、数组、字符串、数字或布尔值会返回 400。
字段与值当前仅允许按下表使用 templateKey，值为已登记且启用的模板标识字符串。不要传自定义键名、嵌套对象、数组或其他类型作为能力参数。
大小Python 重新序列化后的 UTF-8 JSON 不超过 65,536 字节（64 KiB），包含键名、标点等开销；不是字符数，也不是只计算字段值。中文通常占多个字节，建议留出余量。
层级根 payload 记为第 0 层，每进入一个对象字段值或数组元素增加 1 层；检查到的任意值深度不得超过 16。
非空请求input 对象始终必填；去除首尾空白后的 input.text、非空 attachmentRefs、非空 payload 至少满足一项。仅传 payload 时也要提供 "input": {}。
生效范围属于当前 Run；不会作为后续消息的默认请求配置。下一次选择能力或预制模板时应重新显式传值。

现行大小计数使用 Python json.dumps(payload, ensure_ascii=False, allow_nan=False) 后的 UTF-8 字节数，含其默认分隔符空格；压缩 HTTP JSON 中的空白不能绕过此限制。

保留字段与数据边界

任意层级（包括数组内对象）均拒绝以下键名，比较时忽略大小写、下划线和连字符。例如 apiKey、API_KEY、api-key 都会被拒绝：

禁止作为 payload 对象键名的字段
credentials, platformBearer, authorization, token, apiKey, secret,
tenantId, userId, workflowRef, skill, skills, agent, agents,
model, tools, mcp, mcpServers, mcps, cwd, workspace, permissions

这是字段名检查，不是秘密识别或内容脱敏。将密码换个键名、放进字符串或 Base64 并不会变安全。payload 会被模型读取并可能出现在回答或运行记录中；不得放密码、Token、个人敏感身份信息、连接凭据、文件字节或执行配置。业务凭据走 credentials.platformBearer，模型和数据库配置由部署侧维护。

返回、重试与失败处理

payload 没有独立返回接口。创建成功仍返回 Run 状态及 eventsUrl，查询 Run 和会话执行列表不会原样回传请求 payload；模型生成结果通过 SSE 或 Artifact 获取，不承诺与输入字段一一对应。

阶段 / 结果含义与处理
400：请求格式错误payload 顶层类型错误、保留字段、非 JSON 值、超出大小或深度限制等，会在创建时拒绝。通常返回 text/plain 错误信息；修改输入后再提交。
409：幂等冲突同一 runId 已登记后，修改合法 payload 或其他参与幂等比较的业务字段会冲突。改变业务输入应使用新 runId。
202 / 200：请求已接收首次创建通常返回 202，相同请求重试返回 200。重试保留原业务字段，并以新 jti 签发 JWT；payload 省略与 {} 等价，null 不等价且非法。
后续 run.failed模板资源与能力绑定等检查发生在异步执行准备中；可能先返回 202，再通过 SSE 报告 run.failed，查询状态为 failed。不能将 202 当作模板已通过或文档已生成。

请求格式检查、模型处理和模板资源校验是不同阶段；例如 {"templateKey": "unknown-template"} 可以通过通用 JSON 检查，但随后会因模板未登记而失败。Java 应同时处理创建接口的 HTTP 错误和执行过程中的失败事件。

Python 的内部图表工具校验标签与数值后生成 Mermaid，由模型安排正文位置；Runtime在终态前核对完整图块并补齐遗漏结果，已出现的同一图表不重复追加。工具参数不是 Java 请求字段，不能放进 payload。当前每张图一个数值系列，两类柱状图、折线图和矩形树图最多 50 项，饼图最多 12 项，雷达图 3–12 项；折线图至少 2 点。数值绝对值不超过 1015，不接受 null、布尔值、数字字符串或非有限数值；分类标签不能重复。饼图合计须大于 0，且每个正值占比至少 1%（当前渲染器会省略更小的扇区）；不符合时改用柱状图或表格，不能删除或擅自合并小项。雷达图上限取本组最大值（全零时为1），不代表满分；矩形树图不接受零值，极小分类应在正文补充原始数字。不得擅自改数或截断数据。

按业务会话查询执行记录

用于查询某个业务会话在 Python Runtime 中发起过哪些执行，以及每次执行的当前状态。例如用户重新打开会话时，Java 可通过此接口取得 Run 列表，再按 messageId 关联自己保存的业务消息，显示“执行中”“已完成”或“失败”等状态。

查询范围是 JWT 授权的同一租户、同一用户、同一业务会话，包含该会话下各能力的执行摘要。接口不返回聊天正文、会话标题、内部 metadata 或 SDK 会话；业务会话和消息仍由 Java 保存。需要执行详情、事件或生成文件时，取得 runId 后调用对应的 Run 接口。

GET/internal/v1/sessions/{businessSessionId}/runs

输入：会话标识与分页参数

此接口没有请求体。会话标识放在路径中，分页参数放在 URL 中，JWT 放在请求头中。

参数位置 / 类型说明
businessSessionId路径 / string必填。Java 维护的业务会话标识，例如 session_01；必须与 JWT 中的同名字段一致。
limit查询 / integer可选，每页最多返回的记录数。默认 50，范围 1–100。
cursor查询 / string可选，最长 345 字符。第一页不传；下一页使用上一页返回的 nextCursor，不要自行生成或修改。
请求示例：查询 session_01 的第一页
GET /internal/v1/sessions/session_01/runs?limit=50
Authorization: Bearer <包含 session.read 权限的 JWT>
Accept: application/json

鉴权：Java 签发会话读取 JWT

Java 先校验当前用户是否有权访问该业务会话，再使用与 Python 约定的密钥签发短期 HS256 JWT。以下是签名前的 claims 示例，不是请求体，也不是可以直接放进 Authorization 的 Token：

会话读取 JWT 的 claims 示例
{
  "iss": "string-ai-center-service",
  "aud": "ccsdk-runtime",
  "iat": 1725400000,
  "exp": 1725400600,
  "jti": "session_read_01",
  "tenant": "tenant_01",
  "sub": "user_01",
  "businessSessionId": "session_01",
  "scope": "session.read"
}

以上字段均必填。iss、aud 必须匹配部署配置；tenant、sub 来自 Java 已认证的租户和用户。示例时间仅说明格式，实际签发时将 iat 设为当前 Unix 秒、exp 设为短期过期时间。这里不要求 runId 或 capabilityRef。

只读分页不消耗 jti，同一 Token 可在有效期内查询多页。run.read / run.execute 不能代替 session.read；反过来，会话读取 Token 也不能直接查询或控制单个 Run，调用那些接口需要另行签发对应 Run JWT。

    {

分页与错误处理

记录按创建时间倒序排列，创建时间相同时按 Run ID 倒序。若 nextCursor 非空，Java 将其作为下一次请求的 cursor 查询参数（由 HTTP 客户端编码），并继续携带有效 JWT。游标本身不授予访问权限。

分页结果不是某一时刻的固定快照；查询期间产生的新记录应通过重新请求第一页获取。成功响应带 Cache-Control: no-store，不得缓存。

HTTP 状态含义
400游标无效，或不属于当前 JWT 授权的租户、用户及会话范围。
401JWT 缺失、无效、过期，缺少 session.read 权限，或 businessSessionId 与路径不一致。
422分页参数不合法，例如 limit 不是整数或超出 1–100，cursor 长度超过 345。
503Python Runtime 未配置 JWT 校验密钥。

字段含义前端如何使用
type发生了什么，例如 tool.started 或 message.delta。决定这条事件要更新正文、工具、文件还是整次请求。
payload.displayNamePython 字典提供的中文显示名称，允许空字符串；不是模型自由生成的文字。非空时显示状态名称；空字符串时不新增状态提示。不用于判断成功或失败。
payload.toolKey仅工具事件包含，稳定的公开工具分类，例如 data.query；不是内部工具名，也不授予调用权限。可用于选择图标。多次查询可能有相同 toolKey，不能用它区分每次调用。
payload.toolCallId上游提供时返回，标识这一次工具调用。同一 Run 内结合 scope 关联开始、进行中和结束；不同 Run 不共用调用记录。

一段段回答如何显示

三个工具事件还带 scope：main 表示主助手，sub:... 表示内部子任务；用于区分工具状态，不是回答文字。它们不返回工具的具体输入或结果内容。

sequence 是同一次 Run 中所有事件的序号，从 1 开始递增。它不是字数，也不是“第几段回答”；工具、步骤和文件事件同样占用序号，所以两段回答的序号可能不连续。

依次收到的事件本次操作页面上的完整回答
sequence=4，message.delta，textDelta 为“你好”加入第一段文字你好
sequence=5，phase，name 为 thinking只更新状态提示，正文不变你好
sequence=6，message.delta，textDelta 为“，有什么可以帮你？”在末尾接上新文字，不替换已有文字你好，有什么可以帮你？
重连时又收到 sequence=6已处理过，忽略这条重复事件你好，有什么可以帮你？

每个 runId 单独保存“最后成功处理的 sequence”。按服务返回的顺序逐条处理，处理成功才更新序号；重连从这个序号继续读取。不要只给 message.delta 计数，也不要自行增加空格或换行，按 textDelta 原文追加。

通常顺序为 pending → uploading → ready / failed / unknown；配置缺失等可由 pending 直接 failed。多个文件的事件可能交错，按 artifactId 分别更新。SDK 结束后若仍有上传，发送 phase.name=saving_files，Run 保持 running；待全部文件进入终态，再发 run.completed / run.failed / run.cancelled。Run 的终态描述执行结果，run.completed 不保证每个文件都 ready，必须检查各文件状态。

Python 内部处理有限自动重试，期间文件保持 uploading，不发送中间失败事件；成功发 artifact.ready，最终失败发 artifact.failed。上传及重试共用时限，所有已提交文件收尾后才发 Run 终态，不再提供外部重传接口。Java 正常订阅 SSE 即可接收结果，GET 仅用于补查。

断开 SSE 不取消上传；事件按 sequence 持久化并分页回放。重启仅恢复尚未发送的 pending，原 uploading 转为 unknown，ready 保留，不重新启动终态文件。未收到可信响应、无法确认远端结果时为 unknown，不自动重传。取消 Run 不撤销已提交上传，最终仍由文件事件和 Run 终态报告收尾。

Java 与前端的对接约定：Java 通过创建时保存的 runId → messageId 关联找到业务消息，按 artifactId 幂等更新文件记录；收到 ready 后保存 fileId 并校验文件访问权限。前端把正文增量与文件卡片分开显示，只有业务下载入口就绪后启用下载。回答中提到的文件名、Markdown 链接或 URL 均不作为文件登记凭据。本次实现 Python 接口，Java 关联及前端卡片需接入方实现。

公共事件只暴露阶段、文件元数据、回复增量和工具生命周期。工具参数、工具结果正文、Prompt、内部文件路径、凭据和 Provider 原始消息不会进入此接口。模型主动写在回复正文中的内容仍需业务展示层处理。

自动上传与最终结果

上传重试由 Python 内部完成，Java 无需发送重传请求，不新增 JWT scope。每个文件最多尝试 3 次，第 2、3 次之前分别等待 2 秒、5 秒；所有请求和等待共用 fileService.timeoutSeconds 总预算，预算用尽可提前结束。重试只读取原快照，保留 artifactId，不重新调用模型，也不再次生成文件。

上传结果Python 行为发给 Java 的最终事件
HTTP 2xx、state=200、success=true，文件信息有效保存文件服务返回的 fileIdartifact.ready
HTTP 500，或 HTTP 2xx 响应中的 state=500按文件服务约定视为明确失败，自动重试成功则 ready；次数或预算耗尽则 failed，error=file_upload_server_error
连接建立失败、连接超时或连接池等待超时自动重试耗尽后 failed，error=file_service_unreachable
配置缺失/无效、文件缺失/超限、明确拒绝直接结束，不重复发送相同无效请求artifact.failed，携带稳定 error
请求发出后响应超时/断开、无效成功响应、其他 HTTP 5xx不能确认远端是否已保存，不自动重传artifact.unknown

500 的重试依据是当前文件服务的失败约定；unknown 与明确失败不同。整个重试过程只发送一次 uploading，最终只发送一次 ready、failed 或 unknown。详细尝试日志留在 Python，不要求 Java 调度或轮询重试。本节只定义 Python → Java 契约，Java 与前端的交互由接入方决定。

部署侧文件服务配置

在 config/databases.json 顶层增加 fileService，与 version、sources 并列。仍由 CCSDK_DATABASES_FILE 指定配置文件，默认项目根目录下该文件；下面是新增字段片段，合并时保留现有数据源配置。修改后重启服务；镜像内配置需重建镜像。

配置片段 · fileService
{
  "fileService": {
    "baseUrl": "https://newtest.stringedu.com",
    "domainName": "newtest.stringedu.com",
    "remoteUrl": "https://newtest.stringedu.com",
    "downloadPath": "/fwk_manage_service/sys_attachment/{fileId}/ai/download/",
    "timeoutSeconds": 600,
    "maxFileBytes": 1073741824
  }
}

Python 向 baseUrl 下固定路径 /fwk_manage_service/sys_attachment/ai/upload/ 发 POST，multipart 字段名为 file，请求头 domain-name / remote-url 分别取对应配置；HTTP 客户端自动生成 multipart boundary。三个地址字段必填；baseUrl、remoteUrl 只接受 http(s) 来源地址，不带业务路径、查询或账号密码。timeoutSeconds 默认 600（1–3600），限制一个文件全部上传尝试及等待的总时间；maxFileBytes 默认 1 GiB（1 字节至 10 GiB），为单文件上传上限；下载与CCSDK_FILE_MAX_BYTES取较小值。downloadPath是含{fileId}的站内路径，仅下载必填。配置不代表总磁盘配额。

只有 HTTP 2xx 且业务 state=200、success=true、data 中 ID 与文件大小等字段合法，才记录 ready。data.id 映射 fileId；data.url 只在内部保存，当前是存储路径，不能拼成已确认可下载的 URL。上传在 Runtime 父进程完成，不把服务配置主动注入模型，不转发 Run JWT 或业务 Token，不跟随重定向。domain-name、remote-url 不是鉴权凭据；文件服务未提供租户 ACL，Java 仍须做消息归属和下载授权。当前 Agent 具有进程文件权限，这不构成生产凭据沙箱。

常用错误码：file_service_not_configured、file_service_config_invalid、artifact_snapshot_missing、artifact_too_large、file_service_unreachable、file_upload_server_error、file_upload_rejected（failed）；file_upload_response_invalid、file_upload_http_error、file_upload_uncertain（unknown）。file_upload_interrupted、file_upload_error 需结合 status 判断。unknown 需与文件服务核对结果。

cancel取消本次 Run，包括排队中的执行；执行取消后产生 run.cancelled 事件并进入 cancelled。业务前端的“停止生成”使用此值。

Python → 文件服务

下载与成果上传共用数据源配置文件顶层 fileService 的 baseUrl、domainName、remoteUrl；downloadPath 配为 /fwk_manage_service/sys_attachment/{fileId}/ai/download/。下载目标仅由部署配置确定，不接收用户 URL；不再从 backendService 拼接 Broker 地址。

请求 · GET
GET <fileService.baseUrl><downloadPath，替换 fileId>
domain-name: <fileService.domainName>
remote-url: <fileService.remoteUrl>
Accept: application/octet-stream

仅发送配置头，不转发 Run JWT、业务 Token 或 Cookie，不跟随重定向。当前文件端点不检查业务 Run ACL，Java 必须在创建 Run 前校验文件权限；取得文件不等于授权完成。

响应须为 200 文件流，Content-Disposition 提供安全文件名（支持平台 URL 编码及 RFC 5987）；有 Content-Length 时校验长度，无长度时流式计数并限制大小。服务没有返回权威 SHA-256，本地摘要仅记录实际内容，不作为远端指纹比对结果。

Client 输入位于 .scribe-runs/client-sessions/<scopeHash>/.current-input/，Query 输入位于 .scribe-runs/work/<runId>/input/。文件全部准备完成后才查询 SDK；失败、取消及终态清理输入，不删除远端原件。工作稿另存 .work/，交付快照按发布生命周期保留。

独立部署及 ScribePlayground 可显式配置 CCSDK_FILE_BROKER_URL 使用 POST Broker，保留代理流/一次性 URL 校验；平台下载失败不自动切换。完整契约见 Runtime 文件规范。
