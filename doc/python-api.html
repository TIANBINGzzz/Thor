Python Runtime 接口

本文档是 Python Runtime 提供给 Java 业务层的接口契约。Java 负责业务会话、用户权限和文件 ACL；Python 负责 Capability 执行、SDK 会话、Run 状态、事件和交付物。

目录

变更规则

  1. 字段、路径、状态、事件、JWT Claim 或 File Broker 头发生变化时，同步更新 Runtime 规范、Java 设计、本文档和协议测试。
  2. 请求与响应示例必须能按当前 Python Runtime 代码解析；页面只保留当前代码已经接入的接口。
  3. Capability 目录只读；执行通过 Run 的 capabilityRef 选择，内部执行配置由 Python 维护。
  4. 本地自测通过中间层模拟 Java，不改变本页面记录的 Java 接口契约。

基础约定

Base URL由部署配置提供；本文路径均相对于 <RUNTIME_BASE_URL>。
调用方向Java 业务层调用 Python Runtime；浏览器不直接调用这些接口。
Content-TypeJSON 请求使用 application/json；事件使用 text/event-stream；交付物下载返回文件二进制。
鉴权请求头以下所有 Run 接口都必须发送 Authorization: Bearer <Run JWT>，包括 SSE 和 Artifact 下载。credentials.platformBearer 仅用于业务 MCP，不能代替 Run JWT。
字符集UTF-8。
ID字母、数字、_、-，首字符必须为字母或数字，长度不超过 256。
Run 状态queued、running、waiting、succeeded、failed、cancelled。
Java 只提交业务字段和 capabilityRef。Workflow、Skill、MCP、模型、工作目录、工具参数和 Provider Session 均由 Python Runtime 内部决定。

创建 Run

POST/internal/v1/runs

Java 为每次执行生成唯一 runId 和 messageId，签发带 run.execute scope 的 Run JWT，然后提交请求。相同请求重试保持原 runId，并用新 jti 签发 Run JWT。SDK 的 session_id 由 Python 内部关联，不替代此执行标识。

Request headers
Authorization: Bearer <Run JWT>
Content-Type: application/json
Request body · agent-run/v1
{
  "protocol": "agent-run/v1",
  "runId": "run_01",
  "messageId": "message_01",
  "businessSessionId": "session_01",
  "capabilityRef": "document-writing",
  "payload": {"reportTitle": "年度工作报告", "year": 2026},
  "input": {
    "text": "请整理这个文档",
    "attachmentRefs": [
      {"fileId": "file_01", "purpose": "input"}
    ]
  },
  "credentials": {
    "platformBearer": "业务 Token"
  }
}
字段类型必填设计原因和约束
protocolstring是固定为 agent-run/v1，用于识别请求协议。
runIdstring是一次执行的幂等键；同一 ID 的不同请求会被拒绝。
messageIdstring是关联 Java 业务消息；不等同于 Provider Session ID。
businessSessionIdstring否关联连续业务会话；Python 用它选择内部 Session，但不把它当作 Provider ID。
capabilityRefstring / null否普通会话省略或null，内部使用conversation，JWT仍须绑定conversation；选择能力只作用于当前消息，空字符串拒绝。
input.textstring条件必填最长 1,000,000 字符；文字、附件、payload 至少一个非空；input 对象仍必填，可以为 {}。
payloadobject否默认空对象；业务数据追加到当前模型输入，参与幂等比较。支持 JSON 对象、数组和基本值；最多 64 KiB UTF-8 JSON、16 层。除已登记能力字段外不是执行配置，不自动获取其中的文件引用。
input.attachmentRefsobject[]条件必填最多 64 项；每项使用 fileId 和 purpose，用途只能是 input 或 reference。
credentials.platformBearerstring否仅供受信 MCP 使用；不写入 Prompt、事件、日志或 Run 存储。

新 Run 返回 202；相同请求的幂等重提交返回 200。

payload 用于报告字段、统计条件等允许模型读取的业务数据，不放身份、Token、密钥、文件字节或工具配置。当前不做定制业务字段的确定性校验。相同 runId 修改 payload 返回 409；响应不回传 payload。

payload 保留字段

任意层级均拒绝以下字段名（忽略大小写、下划线和连字符）：credentials、platformBearer、authorization、token、apiKey、secret、tenantId、userId、workflowRef、skill、skills、agent、agents、model、tools、mcp、mcpServers、mcps、cwd、workspace、permissions。字段过滤不能识别所有秘密内容，Java 必须只传允许模型读取的数据。附件使用 input.attachmentRefs，业务凭据使用 credentials.platformBearer。

已登记的能力字段

document-writing 可使用预制模板字段 payload.templateKey。例如：

预制模板请求
{
  "capabilityRef": "document-writing",
  "input": {"text": "生成截至2025年底的双高中期自评报告"},
  "payload": {"templateKey": "szpt-midterm"}
}

templateKey 只能选择 Python 已登记、启用且绑定当前能力的模板；它不是文件路径、数据库名、模板版本或权限参数。模板年份、截止日期和写作要求放在 input.text，外部材料仍使用 input.attachmentRefs。当前 szpt-midterm 由 Runtime 绑定 schoolDoubleHigh 数据源和 hpm 领域查询，Java 不提交连接、SQL、路径或密码。未知、停用、未授权或完整性校验失败的模板会在执行前失败。national-excellence-data-qa 不需要专属 payload 字段，问题、年份和范围要求放在 input.text。

两种模板入口

模板位置Java 传值Python 处理
Python 已登记的系统预置模板payload.templateKey；要求放 input.text校验并加载预制模板，使用绑定的报告流程；模板文件不经 File Broker。
Java 保存的用户自定义模板input.attachmentRefs；不传 templateKey；正文明确模板文件和要求经 File Broker 获取文件，走普通撰写：读取结构、按需收集事实、组织正文、生成新 DOCX；不自动注册预制模板。
自定义模板完整请求
{
  "protocol": "agent-run/v1",
  "runId": "run_custom_01",
  "messageId": "message_custom_01",
  "capabilityRef": "document-writing",
  "input": {
    "text": "以附件《自评报告模板.docx》为模板，保留章节和表格，结合可用数据撰写2025年度报告，缺少依据的数据留空高亮。",
    "attachmentRefs": [{"fileId": "file_template_01", "purpose": "input"}]
  }
}

当前 purpose 仅支持 input / reference，不支持 template；多个附件通过正文明确模板与参考资料。Java 保存文件，Python 按本次授权获取工作副本；再次使用须重新提交附件引用，无需为每个上传模板建立 Python 配置。数据库工具仅在已配置且获准时可用，文件上传不授予数据权限。

若同时传 templateKey 和附件，仍走该预制模板分支，附件不会替换模板。以上附件传递与普通撰写入口已有实现，复杂自定义模板的版式保真和取数质量仍需真实文件验收。

Response 202 / 200
{
  "run": {
    "runId": "run_01",
    "status": "queued",
    "lastSequence": 0
  },
  "eventsUrl": "/internal/v1/runs/run_01/events"
}
创建、查询、控制和取消共用精简 Run 响应：runId、status、lastSequence，失败时可带 error。身份、业务关联和 SDK 执行信息仅在 Python 内部保存。

能力目录与选择

GET/internal/v1/capabilities

返回当前已登记的全部 SDK 能力，无请求正文和分页参数。Java 配置展示并按业务权限筛选后供前端使用；目录本身不是用户授权结果，也不是模型或 MCP 健康检查。创建 Run 时传返回的 capabilityRef。

鉴权：无需 Authorization 请求头，不依赖 Runtime JWT 密钥配置。

Response 200
{
  "capabilities": [
    {"capabilityRef":"conversation","name":"通用对话","description":"日常交流、内容总结与问题解答","supportsAttachments":true},
    {"capabilityRef":"document-writing","name":"文档撰写","description":"起草、修改与生成 Word 文档","supportsAttachments":true},
    {"capabilityRef":"national-excellence-data-qa","name":"双高问数","description":"查询国双高项目、任务、资金与绩效","supportsAttachments":false}
  ]
}
字段类型用途
capabilityRefstring创建 Run 使用的稳定业务能力标识。
name / descriptionstring能力默认名称和业务用途。
supportsAttachmentsboolean是否允许 input.attachmentRefs，供 Java 配置附件入口。

目录只返回公开能力描述。Java 仍须校验用户的能力权限；创建、查询和控制 Run 仍需 Run JWT。

当前能力

capabilityRefPython 内部映射附件业务含义
conversation通用对话配置支持日常交流、总结和问答。
document-writingwriting-docx支持文档撰写、修改和 Word 交付物生成。
national-excellence-data-qadatabase-qa不支持国双高项目、任务、资金和绩效问数。
Java 不提交 Workflow 名称、Skill 列表、MCP 地址、模型、工具参数或工作目录。未知能力返回 400 capability_not_found。

查询 Run

GET/internal/v1/runs/{runId}

使用 run.read 或 run.execute scope。查询请求不消耗 JWT 的 jti。

Response 200
{
  "run": {
    "runId": "run_01",
    "status": "running",
    "lastSequence": 3
  }
}
字段说明
runIdJava 提交的执行标识，用于关联业务消息、查询和控制。
status当前 Run 状态；创建成功仅代表已接收，不代表模型执行完成。
lastSequenceRun 当前已持久化的最大事件序号；0 表示尚无事件。它用于了解事件进度，不是 SDK resume 标识。续传应使用 Java 已成功处理的事件序号，不能直接用查询所得值跳过未消费事件。
error可选；Run 失败时保存的稳定错误码。

按业务会话查询执行记录

GET/internal/v1/sessions/{businessSessionId}/runs?limit=50&cursor=...

Java授权后签发短期JWT，必须包含iss、aud、iat、exp、jti、tenant、sub、businessSessionId和scope: session.read。会话必须与路径相同；不要求runId或capabilityRef，只读分页不消耗jti。Run JWT的run.read/run.execute权限不能替代session.read。

{"runs":[{"runId":"run_01","messageId":"message_01","capabilityRef":"conversation","status":"succeeded","createdAt":1725400000000,"updatedAt":1725400001000}],"nextCursor":null}

limit默认50，范围1–100。按创建时间、Run ID倒序，时间为Unix毫秒。首次不传cursor，下页原样传回nextCursor，null表示结束。无记录返回空数组；游标无效或不属于当前授权范围返回400，分页参数类型/范围/长度错误返回422，JWT无效返回401，密钥未配置返回503。响应禁止缓存。

返回该身份、会话下各能力的执行摘要，不含消息正文、内部metadata或SDK会话。历史messageId可能为null。游标不是授权凭据，列表不是快照；新记录通过刷新首页获取。标题、会话列表及消息仍由Java维护；查询单Run、事件和成果仍使用对应Run JWT。

SSE 事件

GET/internal/v1/runs/{runId}/events?afterSequence=0

使用 run.read 或 run.execute scope。首次订阅从 afterSequence=0 开始；若已成功处理到事件 7，重连时传 afterSequence=7 或请求头 Last-Event-ID: 7，只补取序号大于 7 的事件。查询参数优先于请求头；续传不重启模型执行，也不恢复 SDK 会话。

Request headers
Authorization: Bearer <Run JWT>
Accept: text/event-stream
Last-Event-ID: 3
SSE frame
id: 4
event: message.delta
data: {"protocolVersion":"agent-events/v1","runId":"run_01","sequence":4,"eventId":"evt_04","occurredAt":1725400001500,"type":"message.delta","payload":{"textDelta":"回复片段"}}
事件 typepayload用途
run.startedstatus: "running"Run 已进入执行。
phasename：下表文件阶段或 started、thinking、response、working；思考阶段可带 visible: true展示文件准备和模型执行阶段；不返回思考正文。
message.deltatextDelta助手回复增量，按 sequence 拼接。
tool.startedtoolCallId、toolName、status: "started"展示工具调用开始。
tool.progresstoolCallId、toolName、status: "running"展示工具仍在执行。
tool.finishedtoolCallId、toolName、status: "finished"、isError展示工具完成或失败。
run.completed可选 inputTokens、outputTokens、turns执行成功并结束事件流。
run.failedcode，可带统计字段执行失败并结束事件流。
run.cancelled空对象执行被取消并结束事件流。

文件准备进度

Run 的 running 包含文件准备和 SDK 执行；run.started 不代表模型已经启动。无附件时跳过文件阶段，文件未就绪不查询模型。

phase.name额外字段建议展示
queued无等待当前会话可执行（Client 模式）。
preparing_filesfileCount正在准备模板或附件。
preparing_filefileId正在获取当前文件授权，显示不定进度。
downloading_filefileId、receivedBytes、totalBytes正在准备文件，可展示当前文件的字节进度。
validating_filefileId、receivedBytes、totalBytes正在校验文件，尚未开始模型执行。
file_readyfileId、receivedBytes、totalBytes当前文件就绪。
files_readyfileCount全部附件就绪。
model_starting无正在处理；收到 thinking 后才显示模型思考。
SSE frame · file progress
id: 4
event: phase
data: {"protocolVersion":"agent-events/v1","runId":"run_01","sequence":4,"type":"phase","payload":{"name":"downloading_file","fileId":"file_01","receivedBytes":26214400,"totalBytes":109051904}}

文件逐个获取；receivedBytes / totalBytes 是当前文件进度，不是整个 Run 的完成比例。下载开始报告 0 字节，中间最多每 500ms 更新一次，结束补发最终字节数。授权前没有总大小，显示不定进度；totalBytes 为 0 时不计算百分比。进度事件与回复共用 sequence，支持 SSE 断线回放。断开 SSE 不取消下载。

公共事件只暴露阶段、文件标识与字节数、回复增量和工具生命周期。工具参数、工具结果正文、Prompt、文件路径、凭据和 Provider 原始消息不会进入此接口。

Artifact 交付物

GET/internal/v1/runs/{runId}/artifacts

使用 run.read 或 run.execute scope。省略 name 时返回文件列表，提供 name 时下载指定文件。

Response 200 · list
{
  "files": [
    {"name": "result.docx", "size": 24576}
  ]
}
GET/internal/v1/runs/{runId}/artifacts?name=result.docx

返回文件二进制，并设置 Content-Type、Content-Disposition 和 Cache-Control: no-store。name 只能定位该 Run 关联的交付物目录；独立执行使用 Run 目录，持久会话执行共享会话目录，列表可能包含同一会话之前生成的文件。

控制 Run

POST/internal/v1/runs/{runId}/control

使用 run.control 或 run.cancel scope。控制请求消耗 JWT 的 jti。

Request body
{"option":"interrupt"}

option 是必填字符串，只允许以下两个值：

option执行效果与状态
interrupt文件准备期间等同取消准备，进入 cancelled。模型执行期间请求中断当前响应，不代表可恢复暂停：持久 Client 调用 SDK interrupt，最终状态由随后 SDK 结果决定；独立执行停止任务并进入 cancelled。没有活动任务时不改变状态。
cancel取消本次 Run，包括排队中的执行；执行取消后产生 run.cancelled 事件并进入 cancelled。业务前端的“停止生成”使用此值。

两种操作都不删除业务会话或已有输出，也不撤销工具已完成的操作。已结束的 Run 保持原状态。接口返回当前状态，执行可能仍在收尾，应以之后的 SSE 终态事件或查询结果为准；继续对话需要创建新的 Run。

POST/internal/v1/runs/{runId}/cancel

快捷取消接口，等价于 control 的 {"option":"cancel"}，需要 run.cancel 或 run.control。

Response 200
{
  "run": {
    "runId": "run_01",
    "status": "cancelled",
    "lastSequence": 8
  }
}

鉴权

Java 签发短期 HS256 JWT，并放入 Authorization: Bearer <JWT>。能力目录无需鉴权，Run 接口使用本节 Run JWT。Python 使用 python/runtime/auth.py 对 JWT 做 HMAC-SHA256 校验。

密钥和部署配置

Python 本地配置位置为项目根目录 .env（参考 .env.example，不是 python/.env）；部署时也可注入进程环境变量。启动时根目录 .env 中的同名值会覆盖进程环境，修改后须重启 Python 服务。唯一密钥配置名为 CCSDK_RUNTIME_JWT_SECRET，不再读取旧别名 SCRIBE_RUNTIME_JWT_SECRET。

Java 对应 Spring 配置项为 ai-center.runtime-jwt-secret（环境变量 AI_CENTER_RUNTIME_JWT_SECRET），必须与 Python 使用相同的密钥值；可通过服务端配置或 Secret/Nacos 注入。下方仅为占位示例，真实密钥不写入本公开文档。建议生成至少 32 字节的随机值，双方使用相同字符串。

Java 与 Python 的服务端共享配置
CCSDK_RUNTIME_JWT_SECRET=<服务端随机密钥>
CCSDK_RUNTIME_JWT_AUDIENCE=ccsdk-runtime
CCSDK_RUNTIME_JWT_ISSUER=string-ai-center-service
配置设计约束
CCSDK_RUNTIME_JWT_SECRET非空随机密钥，只放 Java/Python 服务端环境或 Secret Manager，不进入浏览器、代码库、日志和请求正文。
audience / issuerJava 签发值必须分别等于 Python 当前配置；不匹配即拒绝。
算法固定 HS256，Header 为 {"alg":"HS256","typ":"JWT"}。

File Broker 回调契约

文件流转

Java 保存的自定义模板与附件流程
用户上传模板或资料 → Java 文件服务器保存并分配 fileId
选择模板 → 前端显示“已选择”
发送消息 → Java 创建 Run（JSON 中传 attachmentRefs）→ Python 立即返回 202
Python 后台：获取授权 → 分块下载 → 校验并落盘 → 文件全部就绪 → SDK 查询
Python → SSE 准备进度和回复 → Java → 前端
生成文件 → Java 调用 Artifact 下载 → 业务归档或用户下载

“上传中”仅用于用户本机向文件服务器上传。Python 获取已存在的模板时显示“正在准备模板”，不是再次上传。Java 不等待下载完成再响应前端；文件字节经 HTTPS 二进制响应传输，进度经 SSE 传输，不把文件放入 payload。当前无附件的 Run 直接执行，有附件但能力不支持时创建返回 400。

用户上传先由 Java 保存并分配 fileId，Java 在创建 Run 时通过 input.attachmentRefs 传递本次授权文件。Python 在执行前获取文件，模型读取准备好的本地文件；payload 中出现 fileId 不会触发下载。Java 可以直接返回代理文件流，无需另设下载 URL。生成文件由 Java 通过 Artifact 接口取得并向用户提供下载。

这是 Java 必须提供给 Python 的文件授权端点。Python 只提交 runId、fileId 和用途；Java 负责业务会话、用户权限、文件 ACL 和授权有效期。

Python → Java 请求

Request
POST <CCSDK_FILE_BROKER_URL>
Authorization: Bearer <Run JWT 或 File Broker 服务 Token>
Accept: application/json, application/octet-stream
Content-Type: application/json

{"runId":"run_01","fileId":"file_01","purpose":"input"}
字段类型Java 校验
runIdstring校验 Run、业务会话和当前用户权限。
fileIdstring校验文件归属、ACL 和请求用途。
purposestring只能是 input 或 reference。

Java → Python 一次性 URL 响应

Response 200 · application/json
{
  "fileId": "file_01",
  "name": "source.docx",
  "mimeType": "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
  "size": 1024,
  "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "downloadUrl": "https://files.example.com/one-time/file_01",
  "expiresAt": 1725400300000,
  "oneTime": true
}
字段设计原因
fileId防止授权响应对应到另一份文件，必须与请求一致。
name / mimeType用于安全文件名和工具输入类型校验。
size / sha256用于下载后大小和内容完整性校验。
downloadUrl必须是 HTTPS、短时、一次性地址；Python 不跟随重定向，也不转发 Run JWT。
expiresAt / oneTime限制授权有效期和重复使用。

Java 代理流响应

如果 Java 不返回 URL，则直接返回文件字节，并带有以下完整性头：

Response headers · application/octet-stream
X-File-Id: file_01
X-File-Name: source.docx
X-File-Mime-Type: application/octet-stream
X-File-Size: 1024
X-File-Sha256: 0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef

Python 按最多 256 KiB 分块写入临时文件并计算 SHA-256，校验成功后才将文件提供给 SDK；不把整个大文件载入内存。取消或失败清理临时文件，Run 完成后清理临时输入，不删除 Java 原文件。这里的校验是传输完整性校验，不代表 DOC/DOCX 内容已被工具成功解析。

大小和独立超时

配置默认值含义
CCSDK_FILE_MAX_BYTES268435456单文件 256 MiB。
CCSDK_FILE_PREPARE_TIMEOUT_MS600000本次全部附件准备 10 分钟。
CCSDK_FILE_BROKER_TIMEOUT_MS15000连接和等待数据等单次网络操作 15 秒，不是整份文件下载时长。
CCSDK_RUN_EXECUTION_TIMEOUT_MS300000文件就绪后单独计时，模型执行 5 分钟。
CCSDK_CLIENT_QUEUE_TIMEOUT_MS300000Client 排队等待 5 分钟。

文件准备超时通过 run.failed 返回 file_broker_timeout，排队超时为 run_queue_timeout；模型执行超时 Query 为 timeout，Client 为 sdk_timeout。文件错误也保存为 Run.error。取消使用 option: cancel，在准备期间同样有效。Java 须确保文件授权 Token 在排队后和后续文件请求时仍有效，Python 不会自动刷新。

错误响应

Runtime 错误使用 text/plain; charset=utf-8，Java 应按 HTTP 状态和稳定错误码处理，不把错误正文当作 JSON 解析。

HTTP含义常见场景
400请求无效JSON、字段、Capability、附件或 control 操作不合法。
401Runtime 鉴权失败JWT 缺失、签名无效、身份绑定不一致或 scope 不允许。
403请求来源被拒绝内部 Runtime 请求带有浏览器 Origin，或不满足服务间调用边界。
404资源不存在Run 或 Artifact 不存在。
409状态冲突幂等请求归属/内容不一致，或 Run 状态不允许当前操作。
421Host 不允许请求 Host 不是当前 Runtime 地址。
504控制超时中断或取消命令在控制窗口内未完成。
503Runtime 配置不可用Runtime JWT 配置缺失（Artifact 接口此时返回 401）；File Broker 配置或文件访问错误会在 Run 事件中返回稳定错误码。
Error response · text/plain
capability_not_found
