## 背景

当前 `bypassPermissions` 和完整工具预设允许执行命令，单个文件工具的路径校验不足以构成隔离。

## 决策

- 拟将 Agent 放入容器，只将 `/workspace/session/<id>` 挂为可读写、`/workspace/project` 挂为只读，其余目录不挂载。
- 保留受控命令执行能力；容器运行时、镜像、网络和资源策略尚待评审，不把提议当作现行生产保障。

## 实现证据与差距

- 范围：Agent 执行环境隔离；尚无本决策的容器部署实现。
- 验证：[config.py](../../python/runtime/config.py) 仍使用 `bypassPermissions`，[process.py](../../python/runtime/process.py) 直接启动本机 Worker；本次未发现项目自有 Docker/Compose 部署文件。
- 差距：运行时与镜像选型、挂载、网络/资源限制及逃逸验证均未完成。

## 后果

- 好处：可由操作系统隔离文件访问，保留受控命令能力。
- 代价：新增镜像、部署和本机开发适配工作，Windows 环境需额外验证。
- 风险：仅挂载隔离不足以保证生产安全，仍有容器逃逸、网络外连和资源耗尽风险。
