## 背景

上传、引用、预览与流式会话跨前后端，曾出现上传失败仍发送、引用无法解析、产物不进入上下文和刷新丢失消息。

## 决策

- 发送前上传所有待处理文件，任一失败则不发送；服务端按本次实际新增文件返回记录，上下文包含上传文件和可见交付物。
- 增加 `@file:`，服务端复核项目路径、存在性和大小；下载使用附件响应，图片/PDF 通过 Blob URL 预览并及时释放。
- 本地聊天仅在真实断线时结束流式执行；先持久化 turn，再周期更新事件；文档任务要求最终交付有效 `.docx`。
- 生产内部 Run 的断线语义由 ADR-013、014 规定：订阅断开不取消后台 Run；本地会话产物目前须先显式发布。

## 实现证据与差距

- 范围与代码：[ChatWorkspace.tsx](../../web/app/components/ChatWorkspace.tsx)、[sessions.py](../../python/local/sessions.py)、[references.py](../../python/local/references.py) 和 [server.py](../../python/server.py) 已覆盖上传阻断、引用复核、预览及流式落盘。
- 验证：[test_session_store.py](../../python/tests/test_session_store.py)、[test_references.py](../../python/tests/test_references.py)、[test_server.py](../../python/tests/test_server.py) 随本次 Python 测试通过。
- 差距：未重跑真实上传失败、长对话刷新、Blob 预览及最终 DOCX 可打开性验收；Prompt 中的文档要求不能等同于有效文件验证。

## 后果

- 好处：上传事实、文件清单和上下文一致，刷新可恢复已持久化消息。
- 代价：维护上传队列、Blob URL 生命周期和周期会话写入。
- 风险：大文件增加等待，候选缓存短暂滞后；本地断线行为不能当作生产 Run 契约。
