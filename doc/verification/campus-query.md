# 校园大脑问数验收

核验日期：2026-09-23。范围：Python Runtime、真实模型与校园 MCP；不代表 Java 或生产环境验收。

## 实现与配置
- `campus-brain-query` 复用 Agent 与既有会话，不新增 Workflow；普通 input.text、agent-run/v1、SSE 和内部 credentials.platformBearer 保持不变。本版仅文字问数，不接收附件。
- [内部配置](../../.claude/capabilities/campus-brain-query/capability.json) 管理固定地址、静态 Header、工具参数、输出字段、max_calls 和独立 minimum_schools；后者同时生成工具 Schema 与指令。
- 指标知识按分析类型分别保留402条记录，学校1658条；只按需返回候选，保留前导零、名称、类型和源年份，不向模型整表注入。
- 模型只看到知识检索与三个查询工具；凭据由进程内适配器发送时绑定，异常正文不回传，统计字段按类型过滤。Client 每轮重置身份与预算，凭据变化沿用现有指纹重建。

## 真实接口核验
- Header 单独鉴权返回 -32001；顶层 user_context_token 调用身份、本校指标及常模成功。限定例外见 [ADR-035](../ADR/035-campus-query-adapter.md)。
- 远端 Schema 描述仍写“最少12个”，但7所请求失败，8、11、12所均成功；运行默认 minimum_schools=8，与参考流程一致。上游描述与实现需服务维护方统一。
- 本校身份返回 school_id/school_name；预置群体统计在 scoped_metrics 中；常模返回本校值、排名与匿名聚合。只放行已核对字段，不公开逐校明细。

## 测试与效果
- `npm test`：312项通过；含17项校园专项，覆盖配置/白名单、缺凭据、隔离、预算、重定向、JSON/SSE、类型过滤、知识冲突与配置联动。独立审查发现的SSE等待EOF、字符串数值绕过均已修复并复验。
- 用户提供的《职业院校对比与常模分析测试问题集》77题全部执行：72题独立SDK请求，5题使用同一业务会话走带Run JWT的真实Runtime HTTP/SSE入口（本地ASGI传输），下游模型及MCP未替换。
- 73题满足本次检查项；4题（41—44）对“宁职大”等简称保守澄清，未发起业务查询，尚未达到题集“高置信简称自动执行”预期。不硬编码简称或猜测学校。
- 已核对对比/常模分流、指标与年份组合、学校去重/数量、外校零调用拒绝、内部信息拒绝、超预算零业务调用、三年逐年查询与学校变更继承最近年份。
- 首轮发现的外校问题多余身份调用、数量不足改查本校、年份追问扩大范围已修正并复验。2题首次知识工具JSON格式错误后由SDK提示纠正，未造成业务重试或错误结果；不是零错误率保证。
- 6次HTTP入口请求均完成，未签名请求拒绝，SSE序号有序；5轮续聊确认2024→2023、增校后仍仅查2023。公共事件、私有观测及该测试目录持久化材料未发现原始业务Token。
