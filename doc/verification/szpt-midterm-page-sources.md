SQL-S01（本页）含义：按单个项目、单个阶段统计有效三级任务数，计算 `ROUND(AVG(COALESCE(progress_,0)),2)`；没有“每项超过 100%”校验、历史快照、累计完成度或评分计算。
现有 `task_progress_summary` 可作为 M01/M02 的查询入口，但其任务国双高标记、租户和年度规则须披露，不能宣称与原 SQL 完全相同；执行不复制文档里的项目/阶段常量。
本段是 **SQL 取事实后由 AI 整段撰写**：输入应含对象、期间、指标定义、实值、单位、缺失情况和查询来源；有依据才做比较，不强制维持“均超”“优”等样例结论。
本页待确认：任务数量采用三级任务；平均进度与逐项达标分开表述；累计完成度、自评分及等级暂列待定义。

## 物理第 5 页 表 1 自评得分表（页脚 2）

- 表格有“高水平学校建设任务评分”“高水平专业群建设任务评分”两块。**每块的 100 位于纵向合并的总分单元格，不是每个二级指标都得 100 分。** 专业群块是否合并多个群，原文未说明。
- 两块均列四类一级指标：产出 50%、效益 30%、满意度 10%、管理与执行 10%；二级为数量 20%、质量 20%、时效 10%、社会效益 15%、可持续影响 15%、服务对象满意度 10%、资金管理 5%、项目管理 5%。
- 来源分开：一二级分类的数据库线索为 `t_hpm_project_performance`（D02）；表格评价框架、权重、满分及计分规则来自适用评分办法（R01、M05）。库内分类与正式评分表是否一一对应需要核对，不能见同名就认定相同版本。
- 表后红字明确“自评得分未知”；第 6–9 页 SQL 提供分类与进度参考，未计算表中的政策权重或自评总分。
- AI 分工：根据核验后的分类和评分事实组织表格及解释；不能生成分数、权重或等级。评分结果应先按规则计算/取值再使用。
- 取数顺序：定位对象 → 查绩效模块是否分阶段 → 获取绩效分类树 → 与适用评价框架核对 → 另取评分依据和结果。`performance_tree` 可提供结构，但覆盖多个阶段，必须按模块和期间筛选。
- 待确认：本表采用“分类来源＋独立评分依据”两部分；学校与专业群评分对象关系、权重版本和得分规则待定义。
