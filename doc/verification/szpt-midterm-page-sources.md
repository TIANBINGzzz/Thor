# 双高中期自评报告逐页来源整理

## 暂行整理与撰写规则

1. 先逐页理解正文、表格和批注，再按“查指标 → 执行SQL/获取材料 → 核验事实 → AI撰写 → 核对来源”处理，不按槽位机械填数。
2. 每页都与用户确认，可每五个正文页集中讨论；记录区分“已阅读”“SQL已验证”和“用户已确认”，不互相替代。
3. SQL是紧邻上方段落或表格的来源参考；理解、核验并沉淀到指标库后，不再记录SQL页或分析过程。混合页只记录正文和表格，页码仍以原件为准。
4. 所有正文和表格来源集中在本MD，直接引用指标库中文名称，并注明使用哪个输出；指标定义、参数和SQL统一放在配套YAML。
5. 指标仅保留 id、name、description、parameters、grain、sql、output、validation 八个字段；不写status。最终SQL必须在实库验证后才能登记，未定义项仅留在所属页面，不能编造公式或占位SQL。
6. parameters只列业务参数；tenant_id由执行端统一注入，SQL保留租户过滤。项目限授权范围，使用参数化只读查询；凭据、真实租户值、内部ID和结果明细不提交Git。
7. 模板数值、学校/项目名、时期及获奖事项只作来源样例，不作为实库核验目标。国双高项目名称以“国双高项目名称”查询为准，学校品牌名另行处理；两个专业群不能自动合为学校建设项目。
8. 报告署期、统计截止日、年度阶段和建设周期分开确认；当前值不是历史快照，年度数不能直接当累计数，无数据、未填报和真实0须区分。
9. AI可组织、比较和总结已核验事实，不能生成成果名称、奖项级别、数字、领导评价、排名或评分。“由AI生成”批注不授权无依据撰写。
10. 成果按名称、时间、级别、数量、单位及证据核对并去重；反馈条数不等于成果数，新增与累计分开，人数、人次、人日不混用。资金单位和分子分母保持一致，缺失及矛盾须披露。
11. 原件和运行模板的实际改写另行处理；每批本项目记录变更后创建本地Git提交，保留回滚点。
12. 来源确认与数据质量分开：表结构、字段、关联及SQL口径正确，即可确认来源；空结果、测试数据或与模板数值不一致不阻止登记。实际撰写仍须区分有效事实、缺失和异常，不把来源确认当成实绩确认。
