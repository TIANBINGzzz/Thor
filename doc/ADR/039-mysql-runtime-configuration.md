## 背景

用户要求第三方可配置、保存后生效，并明确取消 Nacos、独立模型档案和发布版本体系。

## 决策

十张 ccsdk_ 前缀 MySQL 表保留资源目录与三类能力关联。能力基本字段和模型引用保持独立列，运行策略、预算、附件规则、专属参数和撰写模板名单放入 JSON。基础设置按四组各存一行，静态秘密加密入库。管理端通过模型目录下拉和局部 PATCH 编辑。application.yml 只留配置库引导和宿主参数。

新 Run 在同一事务中按能力读取所需资源并固定到执行结束；同会话续聊重新读取。独立管理 JWT 授权 CRUD，不维护发布表、历史版本或消息广播。代码包、工具 Schema、模板文件和数据口径随 Runtime 部署。

## 后果

新请求依赖配置库可用性；连接池和合并查询控制读取开销，已取得配置的执行不因随后断库而丢失配置。进程设置重启生效，逐 Run 设置热更新，边界见[配置说明](../../config/README.md)。

REQ-001 保留逐 Run 凭据注入；REQ-002 保留可信装配并记录非秘密实际配置。Java 授权、撤销和生产隔离不由本次改造自动满足。
