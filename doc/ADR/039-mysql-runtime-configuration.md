## 背景

用户要求第三方可配置、保存后生效，并明确取消 Nacos、独立模型档案和发布版本体系。

## 决策

十张 ccsdk_ 前缀 MySQL 表保存能力、Skill、模型目录、模型/数据库/MCP 连接、单行全局设置及三类能力关联。固定字段拆列，扩展参数与短列表保留 JSON；能力通过 model_ref 选择目录，管理端支持下拉列表和 PATCH。推理参数和预算并入能力，静态秘密加密入库。application.yml 只留配置库引导和宿主参数；不保留本地客户配置回退。

新 Run 一次一致性读取并固定到执行结束；同会话续聊重新读取。独立管理 JWT 授权 CRUD，保存即生效，没有发布表、历史版本或消息广播。代码包、工具 Schema、模板和数据口径仍随 Runtime 部署，不提供在线换码。

## 后果

新请求依赖配置库可用性；连接池和合并查询控制读取开销，已取得配置的执行不因随后断库而丢失配置。进程设置重启生效，逐 Run 设置热更新，边界见[配置说明](../../config/README.md)。

REQ-001 保留逐 Run 凭据注入；REQ-002 保留可信装配并记录非秘密实际配置。Java 授权、撤销和生产隔离不由本次改造自动满足。
