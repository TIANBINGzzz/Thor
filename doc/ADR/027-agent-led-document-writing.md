## 背景

专用计划、target和草稿字段将写作方法固化为代码，两类模板使用不同工具。用户要求提供丰富可信上下文，由Agent及harness自主完成。

## 决策

- 同一Capability、Workflow和共同规则；规则统一在writing-docx/instructions.md，由配置直接注入，不额外包装为Skill。预制模板只额外加载所选指南及参考DOCX副本，外部字段不变。
- 统一使用通用DOCX、文件、代码、data及Artifact能力，删除专用reports工具和计划/草稿/渲染/验收流水线。
- 保留可信模板登记、实际源文件/规则指纹、数据来源授权、只读查询和结果引用；地图与取数计划仅为维护参考。
- 合并核验完整指南，保留逐页来源历史和主题指标SQL。无证据仍按模板完成分析框架、数据需求和后续动作，标黄不确定内容。

## 后果与差距

新增模板主要维护DOCX、配置和指南；写作方法由Agent选择。程序不再保证逐段证据及页面审阅完成，Agent须实际检查并如实报告。当前完整工具与bypassPermissions不构成生产沙箱；复杂目录、完整报告和真实Java链路仍须端到端验收。
