## 背景

用户要求 HPM 业务查询支持模板复用、多数据库及 Claude 按需调用连接工具；当前资产登记仍混有业务说明和连接引用。

## 决策

- 用户已确认分离方向；具体实现拟采用 DataSource、ConnectionProfile 与可信 Binding，模板及 QuerySpec 引用业务来源，连接随部署和授权上下文解析。
- 拟提供固定的数据源检索、连接、结构查询及固定/动态查询工具；模型用 source_key 请求连接，服务端管理凭据、物理连接与 Run 内句柄。
- 拟复用 DBHub 多库及参数化 Custom Tools；Python 负责业务语义、授权、QuerySpec 装配与结果处理，SQL方言/参数适配需验证。
- 具体字段、职责及实施顺序见[设计方案](../specs/data-source-connections.md)；本轮不修改资产或 Runtime，不将方案写成当前接口。

## 实现证据与差距

- 当前基础：[QuerySpec](../../.claude/query-specs/README.md) 已沉淀；Python 已装配 DBHub 单流程连接，来源登记尚未驱动连接。
- 本次核对本地 DBHub 1.2.0 的多库、ensureConnected、自定义参数查询、nullable限制与错误追踪行为；仅源码核对，不是多库工具联调。
- 差距：分离配置、可信授权上下文、来源句柄、工具门面、参数编译与provider脱敏均未实现；报告库仍待实际绑定。

## 后果

- 好处：连接和凭据变更不影响模板业务定义，同一查询域可复用到不同来源与部署。
- 代价：维护来源绑定、方言/结构兼容性及连接生命周期，逐源验证。
- 风险：只依赖提示词或混用权限/期间/连接上下文会误取数据；执行端须落实权限和完整性检查。
