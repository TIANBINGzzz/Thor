## 背景

公共规则、工具指引和能力正文曾由不同 Python 分支拼接；custom 模式遗漏公共规则，必需核验依赖模型再读 Skill，配置难以核对。

## 决策

- 公共规则归 prompts，业务入口及流程化指引归 Capability，可复用方法归 Skill，操作说明归 Tool，模板指南与数据库语义保持各自权威来源；字段见 [执行资产归属](../python-api.html#execution-assets)。
- prompt_assembly 是项目指令唯一编译入口；Provider 仅装配工具。default/custom 与逐轮 Hook 共用文本，Skill 分必载和按需，指引随实际工具挂载过滤。
- 只替换显式绑定的数值/布尔变量及受控运行时槽位，不执行表达式、不解析连接或环境秘密；文件引用受所有者目录、人工材料排除及大小限制约束。
- 资产预编译与实际执行复用编译器，内部保留来源与未决槽位；能力配置通过源码维护，不提供在线管理接口。
- 保留 Agent 自主执行；不新增 DAG、通用模板语言或持久化资产版本仓库，内容摘要仅用于现有逐 Run 装配。

## 后果与验证

配置可读且可核对；必载正文增加上下文长度，仍受总量限制。统一装配及 HTTP 边界见 test_prompt_assembly、test_runtime_http；SDK 历史续接由 test_system_prompt_cli 验证，测试通过不证明模型遵循规则或成稿质量。
