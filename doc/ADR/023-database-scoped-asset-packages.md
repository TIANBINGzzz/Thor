## 背景与决策

- 问数和撰写共享同一套可信指标及口径；当前唯一来源是校双高 schoolDoubleHigh，hpm 是业务域。来源标识不是物理库名或租户名。
- 每来源一份 `.claude/databases/<source_key>/`：source.json 登记能力和域；schema 维护表列，semantics 维护业务/关联，metrics 按主题 YAML 内嵌指标定义、参数、SQL 和待补原因，检索索引由程序生成。
- 实际连接、凭据和策略由部署配置集中解析，不复制进模板、指标或 Prompt；来源发现不授予权限，工具按本 Run 的可信身份、Capability、模板和范围取交集。
- 模板指南按来源、业务域、指标 ID 引用资产，不复制 SQL。已知定义优先复用；动态只读 SQL 仍须语义明确、来源获准且数据库账号范围受控，不能补造未知口径或历史值。
- 每 Run 绑定数据上下文及配置快照，结果引用不跨 Run；后续多租户连接路由集中在解析边界，不按租户复制知识目录，也不把单租户部署当作行级隔离。
- 当前共享来源的阶段性授权及恢复条件以[数据库管理](../specs/data-source-connections.md#字段与配置)为准；selected 项目范围不能扩大为全校。

## 证据与后果

数据库包、`python/data_access/` 和 `runtime/data_services.py` 已接入；主题 YAML 合并了原 024 的组织方式。历史真实查询核验见[来源记录](../verification/report-source-audit.md)，移动或合并文档不升级未核验查询的状态。文稿证据规则由[共同规则](../../.claude/workflows/writing-docx/WORKFLOW.md)和所选模板指南维护，不在 ADR 重复。

按库维护减少问数与撰写口径分叉；新增来源仍需逐源验证结构、历史期间和业务含义。目录集中不是权限隔离，生产跨租户、Java 授权和撤销链路须独立验收。
